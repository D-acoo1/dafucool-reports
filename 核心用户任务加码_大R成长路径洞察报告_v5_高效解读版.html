00 / Data foundation

先说明数据基础和样本定义

这部分决定后面所有数字怎么理解：这里不是全量新付费用户转化率，而是对“最终成为大R”和“最终成为超30”的两类用户，回看他们成为当前分层之前的充值行为。

样本定义筛选“首个 observed 分层不是大R、不是超30、不是缺失”，且后续在数据窗口内首次进入大R或超30的用户。大R和超30互斥：只要后续成为大R，就归为大R，不再算超30。
“成为当前分层前”怎么算？大R用户统计首次出现“大R用户”标签之前的充值记录；超30用户统计首次出现“超30天付费用户”标签之前的充值记录。这一笔目标分层订单及之后订单均不计入。
概率和覆盖率怎么读？覆盖率=某分层用户中达到阈值的人数占比；区分度=大R覆盖率 ÷ 超30覆盖率；命中后大R占比=达到阈值的人里最终大R占比。

02 / Single transaction before tier

成为当前分层前的单笔充值概况

单笔充值看每一笔订单本身，适合判断任务里的“M阈值”。如果单笔大额阈值能覆盖更多大R、同时较少覆盖超30，说明它区分度更好。

对象订单维度，每笔订单一条记录范围仅统计成为当前分层之前的订单分位在对应最终分层的前置订单金额中计算覆盖用户是否出现过单笔≥阈值
这一模块用于证明什么？判断“单笔大额”是不是识别大R的主信号。重点看 P90/P95、阈值覆盖率、区分度和命中后大R占比。
怎么用？如果一个阈值的大R覆盖率明显高于超30，且命中后大R占比高，就适合作为任务触发门槛。

03 / Daily total before tier

成为当前分层前的单日累充概况

单日累充先把同一用户同一天的多笔订单加总，再看当天总充值。它用于识别“不是单笔很大，但一天内多笔累计冲高”的用户。

对象用户×日期范围仅统计成为当前分层之前的充值日分位在对应最终分层的前置充值日金额中计算覆盖用户是否出现过单日累计≥阈值
这一模块用于证明什么？判断“N阈值”是否能补充单笔规则，抓到多笔累充型用户。
和单笔的关系单日累计通常覆盖更宽，但纯度可能低于单笔；适合作为补充兜底，不一定适合做唯一主规则。

05 / Additional modules

我建议额外保留两个补充视角

你列的四个模块已经覆盖主判断。为了让报告能直接支持产品决策，我额外补两类信息：阈值建议和风险边界。

主触发规则
优先看单笔充值
单笔金额更容易解释，也更能代表即时高付费意愿，适合作为任务触发主门槛。
补充兜底规则
保留单日累计
用于承接一天内多笔累充冲高的人，避免单笔规则漏掉成长型高潜用户。
时间窗口
前3～7天
过早覆盖不足，过晚已经错过干预窗口；前3～7天更适合做加码任务。
局限说明本报告只看最终进入大R/超30的人群，不包含未转化用户，因此不能直接当作全量用户的大R转化率；它更适合用于比较“哪些充值信号更偏向大R”。
