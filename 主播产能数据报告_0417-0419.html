SAME-USER CONVERSION COMPARISON
测算目标：对比同一个付费用户在收礼型 vs 对话型主播面前的收礼转化率差异，验证"收礼型/对话型"分类是否真的能反映转化能力差异（排除"接触强度不同"的干扰因素）。

测算口径 · 04.17-04.18 两天累计：
· 主播分类：付费用户收礼转化率 ≥ 25% 为收礼型、< 25% 为对话型
· 付费分层：合并看（新付费 + 近3付费 + 30日付费 + 超30天付费 + 大R）
· 用户筛选（严格版）：必须同时被收礼型主播和对话型主播完成过任意任务的付费用户才纳入对比
· 单用户转化率 = 在该用户身上完成过收礼任务的主播数 ÷ 接触过该用户的主播数（分主播类型计算）
· 口径 A（用户维度）：每个用户等权重，跨用户求均值
· 口径 B（主播对维度）：汇总所有 (用户, 主播) 对的分子分母

口径 A · 用户维度平均?口径 A 示例
假设只有 3 个付费用户（且都满足严格版筛选）：

· 用户①：被 2 个收礼型接触、2 个都转化 → 收礼型转化率 100%；被 3 个对话型接触、0 个转化 → 对话型转化率 0%
· 用户②：被 2 个收礼型接触、1 个转化 → 50%；被 2 个对话型接触、1 个转化 → 50%
· 用户③：被 1 个收礼型接触、0 个转化 → 0%；被 1 个对话型接触、1 个转化 → 100%

口径 A：对 3 个用户的转化率求均值
· 收礼型 = (100% + 50% + 0%) ÷ 3 = 50%
· 对话型 = (0% + 50% + 100%) ÷ 3 = 50%

特点：每个用户权重相同，不受"某用户被接触主播数多"的影响。

口径 B · 主播对维度聚合?口径 B 示例
用相同 3 个用户场景：

· 用户①：收礼型 2/2、对话型 0/3
· 用户②：收礼型 1/2、对话型 1/2
· 用户③：收礼型 0/1、对话型 1/1

口径 B：把分子分母分别累加后再算比例
· 收礼型 = (2+1+0) ÷ (2+2+1) = 3/5 = 60%
· 对话型 = (0+1+1) ÷ (3+2+1) = 2/6 = 33.3%

特点：相当于每一次"主播接触用户"的事件权重相同，被接触主播多的用户对结果影响更大。
